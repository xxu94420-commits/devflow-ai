# 原创指标字典 v1

DevFlow AI 不将代码行数或提交数等同于个人产出。所有比例按计数加权而非“先算每组百分比再平均”。`n` 是本行实际分母/观测对象数，不是用户数。空分母或缺失样本返回JSON null，页面显示“—”。

## 共同口径

- 时间统一UTC，窗口W=[start,end)，最长366天。前期W'=[start-(end-start),start)。天=86400秒，小时=3600秒。
- 所有查询先按Project.mode隔离live/demo，再按可选project_id过滤。项目数量是当前已登记项目的存量，不是本期新增数。
- C：W内完成且有actual_hours的任务。开放任务不参加完成队列指标；交互耗时不能替代任务总耗时。
- R：W内交付需求；I：W内创建Issue；P：首次正式评审在W内的PR。关闭的PR不是正式评审的替代数据。
- 所有数据是当前数据库记录重算，不是历史状态快照；补录、重新打开、返工次数调整会影响历史报告。
- n=0显示无样本，1≤n<5显示样本不足，n≥5仍仅为描述性统计。该门槛是产品展示保护，**不是置信区间、显著性检验或统计功效证明**。项目数量的n只是存量计数。

| 指标 / API键 | 原创业务定义与公式 | n / 单位 | 局限 |
| --- | --- | --- | --- |
| 需求平均交付周期 delivery_cycle | Σ(completed_at-created_at)/86400 ÷ \|R\| | 已交付需求数 / 天 | 不含未交付需求，存在幸存者偏差；日历时长不是工时 |
| Issue关闭率 issue_close_rate | I中closed_at<end的数量 ÷ \|I\| ×100% | 本期创建Issue数 / % | 创建队列口径；不等于本期关闭量/存量；无法重放reopen历史 |
| PR平均评审时长 pr_review_hours | Σ(first_review_at-created_at)/3600 ÷ \|P\| | 首次评审在W内PR数 / 小时 | 是首次响应等待时间；不等于全部评审劳动时间；未评审PR不进入均值 |
| Commit频率 commit_frequency | W内已采集的唯一SHA数 ÷ 窗口日历天数 | Commit数 / 次每天 | 默认分支+已采集PR提交的并集，不代表全分支；不用于排名个人 |
| 测试通过率 test_pass_rate | W内测试运行Σpassed ÷ Σtotal ×100% | 执行用例数 / % | 重跑算新执行；不表示覆盖率；测试集合不同不可直接比较 |
| 首次测试通过率 first_test_pass_rate | 首轮全部通过的任务数 ÷ 有首轮测试的任务数 ×100% | 首轮测试时间在W内的任务数 / % | 按全部记录中(created_at,id)最早运行识别首轮；补录会改变结果 |
| 缺陷密度 defect_density | C关联且截至end已发现缺陷数 ÷ \|C\| | 完成任务数 / 个每任务 | 特意采用任务分母，不虚构KLOC；检测滞后和任务粒度影响结果 |
| 缺陷修复周期 defect_fix_hours | Σ(resolved_at-created_at)/3600 ÷ 本期解决缺陷数 | resolved_at在W内缺陷数 / 小时 | 未解决缺陷不进入均值，应同时查看任务链路 |
| 返工率 rework_rate | C中rework_count>0任务数 ÷ \|C\| ×100% | 完成任务数 / % | 是受返工影响的任务比例，不是返工次数/提交数；当前累计计数 |
| AI辅助任务占比 ai_task_share | C中uses_ai=true任务数 ÷ \|C\| ×100% | 完成任务数 / % | 人工声明；创建AI记录自动开启标记；不能从GitHub推断 |
| AI建议采纳率 ai_acceptance_rate | W内交互Σaccepted_count ÷ Σsuggestion_count ×100% | 可辨认建议数 / % | 部分采纳以条数记录，0/0未知；与代码质量无直接等价关系 |
| AI任务平均耗时 ai_avg_hours | ΣAI任务actual_hours ÷ AI完成任务数 | AI完成任务数 / 小时 | 任务级人工记录；包含理解、集成、测试与修正，不叠加交互耗时 |
| 非AI任务平均耗时 non_ai_avg_hours | Σ非AI任务actual_hours ÷ 非AI完成任务数 | 非AI完成任务数 / 小时 | 同一耗时协议；未控制经验/复杂度 |
| AI任务时间节约率 ai_time_saving | 合格类型集合K内：100×[1−Σ(nAk×meanAk)/Σ(nAk×meanHk)] | 合格类型AI任务数 / % | 每类型AI/非AI组均≥5且meanHk>0；不合格类型完全排除；界面称“同类任务时间差”；负值不截断 |
| 按任务类型的AI效果 task_types | 每类型显示nA、nH、meanA、meanH；满足门槛时100×(1−meanA/meanH) | 每类型两组样本 / 小时、% | 不推断因果，不混合7种任务组成 |
| 需求变更与交付周期 change_cycle_correlation | R中x=change_count，y=交付天数；Pearson r=Σ[(x−x̄)(y−ȳ)]/√(Σ(x−x̄)²Σ(y−ȳ)²) | 已交付需求数 / r | n<5或任一方差为0返回null；散点始终可见；相关≠因果 |

## 人工修正和返工的区别

AIInteraction.human_modification_count表示集成建议时人工修改轮数；Task.rework_count表示任务已有可验收结果后因缺陷/需求误解重新开发的轮数。一次修改不能自动当成返工，也不能自动算作采纳。任务详情分别聚合Prompt次数、采纳条数、修改次数、缺陷数，避免双计。

## 报告规则

前后期都不为null才显示差值，比例指标用百分点而非相对提升百分比。测试通过率<90%或返工率>20%是明确预设规则，非统计异常检测，不能自动评价团队。代表案例按返工数降序、ID升序选3个，不伪装随机抽样。

## 可复算示例（synthetic，仅示例）

同类任务AI组5个平均2小时，非AI组5个平均4小时，观察时间差50%；把两组各减至4个，界面必须显示未知而不是50%。测试3/4和10/10两次运行，通过率13/14=92.86%，不是(75%+100%)/2。上述数值是口径例子，不是本项目实际提效结果。
